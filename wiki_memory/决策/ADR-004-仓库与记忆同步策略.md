# ADR-004｜仓库与记忆同步策略

## 状态

`active`

## 背景

工程需要在 GitHub 上持续管理，同时保留模型替换、导出、视觉修改和测试过程，避免后续会话丢失上下文。原始 Blender 和视频素材不适合进入网页仓库。

## 决策

以当前目录作为独立 Git 根目录，使用 `main` 分支和 `origin` 远程。每次代码、视觉、运行资产或记忆修改都要同步结构化 wiki memory、运行 lint、创建提交并推送到 `origin/main`。仓库只管理网页工程和运行必需资产。

## 理由

- 远程仓库提供可追溯版本和部署入口。
- 结构化日志把当前状态、决策、知识和历史分开，便于 Agent 快速读取。
- 不提交外层大文件，避免仓库混入原始素材和外部缓存。

## 影响

- 正面影响：每次修改都有代码与记忆的对应版本，远程状态可核验。
- 代价或风险：小的视觉修复也需要完成记忆同步和提交流程。

## 验证方式

- `git status` 干净且分支跟踪 `origin/main`。
- `memory_lint.py check` 通过，MOC 能列出所有日志。
- 远程 `main` 指向本地最新提交。
