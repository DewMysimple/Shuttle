# ADR-014｜当前帧色彩聚焦与微光

## 状态

`active`

## 背景

时间切片展开后，如果所有 PNG 使用接近的透明度，多个浅色兰花姿态会叠加成白雾，播放中的当前帧也不够突出。现有卡片边缘可以保留时间序列，但不能承担主体焦点的全部反馈。

## 决策

- 当前时间焦点使用最高图像透明度，目标约为 `0.96`；相邻、中距离和远距离切片分别降至约 `0.16–0.30`、`0.06–0.14` 和 `0.02–0.06`。
- 当前帧使用更高的运行时饱和度和对比度，其他帧只降低色彩存在感，不把 PNG 直接染成白色。
- 每张切片保留一层默认隐藏的透明纹理副层，使用低强度暖粉色 `AdditiveBlending` 作为焦点光；只有当前时间焦点获得约 `3.8%–6.6%` 的微光。
- 微光权重使用 `frameFloat` 的连续距离计算，播放时相邻整数帧平滑交接；呼吸周期约 `1.7s`，`prefers-reduced-motion` 下保持静态焦点光。
- 收拢状态继续使用 `Math.round(frameFloat)` 作为唯一清晰帧，并保留该帧的静态微光；不增加后处理 Bloom，也不修改运行资产。

## 理由

- 图像透明度的明显梯度能直接建立当前帧、近帧和远帧的阅读顺序，减少浅色主体叠加造成的泛白。
- 独立副层比提高整张图亮度更容易控制，能够让焦点有“被照亮”的感觉，同时不破坏兰花原始色彩。
- 连续焦点权重避免每 1/30 秒切换一次造成闪烁，低幅度呼吸只提供存在感，不抢夺时间播放本身的注意力。

## 影响

- 正面观察时当前兰花更清晰，时间轨迹仍由低透明度的卡片、边缘和远端图像保留。
- 收拢时仍只显示当前时间切片；展开时恢复完整的历史、当前和未来切片层级。
- 每张切片增加一个透明平面，桌面端开销小幅增加；不增加额外图片请求，移动端仍沿用现有 DPR 和粒子降级策略。

## 验证方式

- 检查当前帧、相邻帧、中距离帧和远距离帧的透明度常量与运行时分级。
- 运行 `node --check src/main.js`、`npm run build`、`git diff --check`、`memory_lint.py index` 和 `memory_lint.py check`。
- 浏览器复核首帧、中段、尾帧、播放连续过渡、收拢态和 `prefers-reduced-motion`；确认主体没有再次被白雾覆盖。
