# ADR-009｜长按播放与滚轮缩放

## 状态

`active`

## 背景

原交互通过页面滚动改变时间帧，滚动同时承担页面导航和时间控制，不能直接表达“按住就播放”。用户希望把主界面收敛成一个可持续操作的舞台：长按屏幕播放时间切片，松开暂停；滚轮只控制主体缩放。

## 决策

- 画布指针按下后启动 260ms 长按识别；保持按住时以 30fps 推进 `frameFloat`，松开立即暂停，播放到末帧后停留。
- 如果指针在长按识别前移动超过 8px，则取消长按并进入双轴旋转；长按播放触发后仍消费指针移动，播放和视角旋转可以并行。
- 旋转保持不封顶 yaw，横向每个视口宽度约响应 1.85π；pitch 约每个视口高度响应 100°，限制在 ±90°，并使用更快的短阻尼跟随，避免超出边界。
- 画布 Wheel 事件只修改相机距离目标值，向上滚轮放大、向下滚轮缩小，目标范围为 `3–15.5`，使用更快且可打断的阻尼过渡；缩放焦点跟随当前 `frameFloat` 的连续时间切片中心。
- 页面改为单屏主舞台，不再注册 scroll 事件控制时间帧；键盘空格复用按住播放、松开暂停，保留方向键、`R` 和展开按钮。
- 右侧增加四个控制按钮：“正放”和“倒放”单击启动对应方向，再次点击当前方向暂停；“开头”和“结尾”单击暂停并跳到 `frameFloat = 0` 或 `sliceCount - 1`。
- 播放推进到第 N 个时间切片后，历史切片仍保持可见；它们不是被删除或隐藏，而是和当前、未来切片一起按距离参与透明度分级。
- 画布使用 `touch-action: none`，确保移动端长按与拖拽不会被浏览器默认手势抢占。

## 理由

- 长按的开始和结束分别对应播放与暂停，时间控制更直接，也不会让用户误把页面滚动当成动画控制。
- 右侧按钮为不依赖长按的明确入口；“开头/结尾”提供可预测的边界定位，完整历史轨迹让播放过程可以持续观察前后时间状态。
- 8px 分流死区保留了稳定旋转，同时避免短暂按住被拖动噪声打断。
- 缩放只改变相机距离，不影响 `frameFloat`、yaw、pitch 或展开状态，职责清晰且易于反向操作。

## 影响

- 主界面不再需要 520vh 的滚动区，访问者进入页面即可直接使用长按、拖拽和滚轮。
- 播放由真实帧率推进，166 帧按 30fps 播放约 5.5 秒；播放到末帧后再次长按会从首帧开始。
- 移动端不能依赖鼠标滚轮缩放，但仍可使用长按播放和拖拽旋转；后续需在真实触屏设备复核长按体验。

## 验证方式

- 源码不再注册 `scroll` 监听或用滚动位置写入 `frameFloat`。
- 长按、移动取消长按、松开暂停、播放到末帧、Wheel 缩放和相机阻尼均有对应代码路径。
- `npm run build`、`node --check src/main.js`、memory lint 和资源 HTTP 检查通过。
- 浏览器手动复核长按播放、拖拽旋转与滚轮缩放的互不串扰。
