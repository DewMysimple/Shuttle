# ADR-011｜直线时间切片排列

## 状态

`active`

## 背景

上一版使用 X+Z 联动将切片组织成时间隧道。实际观察时，斜向深度、逐片角度和漂移会让切片看起来像弯曲或 S 形轨迹，也会让“每张切片正着排列”的关系不明确。用户确认改为正面平行的直线序列。

## 决策

- 继续使用 `offset = index - state.frameFloat`，让当前帧始终位于空间焦点的 X=0 位置。
- 可见切片保持正面平行，沿世界 X 轴排列：`x = offset × LINE_STEP × spread`，其中 `LINE_STEP = 0.30`；`y = 0`、`z = 0`。
- 每张切片自身的 `rotation.x/y/z` 固定为 0；卡片、边缘线和透明 PNG 的局部 Z 层级只用于正确绘制，不改变切片朝向。
- 统一 `rotationRig` 仍负责用户的 yaw/pitch 视角旋转；相机保持固定，`spread` 只负责从重叠状态向水平直线展开。
- 保留当前帧/近帧/远帧透明度分级、整体切片组呼吸、粒子、光环和 reduced-motion 分支；这些动效不能改变切片的直线几何关系。

## 理由

- 单一 X 轴使空间关系可预测，能直接消除 S 形和斜向路径。
- 固定朝向让每张 PNG 的正面构图一致，正面观察时当前花卉清楚，旋转到侧面时可看到连续平行边缘。
- 仍保留统一转台，所以作品具备 3D 视角变化，而不是回退为二维图片列表。

## 影响

- 正面不再形成 X/Z 嵌套隧道，而是形成当前帧居中的直线时间序列。
- 展开状态下，未来切片沿 X 轴向一侧延伸；播放过程中 `frameFloat` 更新后，当前焦点继续保持在中心。
- 原 ADR-007 的 X/Z 时间隧道方案只作为历史记录保留，不再是当前实现依据。

## 验证方式

- `src/main.js` 使用 `index - state.frameFloat` 和 `LINE_STEP` 计算位置。
- 代码中不再使用 `DEPTH_STEP`、`LATERAL_STEP`，也不再给切片追加逐片旋转或逐片 Y/Z 漂移。
- 正面、侧面和中段播放状态均检查当前帧居中、直线排列和卡片平行关系。
- 运行 `node --check src/main.js`、`npm run build`、`git diff --check` 以及 wiki memory lint。
