# ADR-016｜真实水平时间切片穿梭

## 状态

`active`

## 背景

旧实现虽然加载多张帧图，但播放发生在固定中心 `focusLayer`：运行时不断替换当前和下一帧纹理，空间切片只承担背景结构。这会形成“单一中心平面播放动画”的伪时间切片。旧的路径跟随采样相机也没有严格正对模型 X-Y 平面，导致构图漂移和残片。第一次重构尝试又把切片做成同一立面上的横向重叠卡片带，不符合用户给出的水平、平行、不相交层级示意。

## 决策

- 改用 `BUTTERFLY_FLAP_FAST_FOLLOW_PATH_1_WING_FLAP_ONLY.blend`，采样源场景 1 到 91 的每个整数帧。
- Blender 临时相机沿世界 Z 轴正对 X-Y 平面，使用固定正交投影并以身体包围盒中心为目标；只渲染三个 `展示_` 网格。
- 91 张 PNG 在浏览器中分别永久绑定到 91 个材质；运行时禁止更换材质 `map`，删除 `focusLayer`、`focusTrail` 和中心动画代理。
- 网页将 PNG 映射到 X-Z 水平平面，时间维沿世界 Y 轴展开；所有平面法线一致、间距为正，因此互相平行且不相交。
- 时间输入、方向键和播放按钮改变 `shuttleTarget`。姿态变化来自不同实体平面的选中与当前帧枢轴穿梭，不来自中心纹理播放。
- 三维视口、层距手势和滚轮映射由 [[决策/ADR-017-Blender式三维视口与时间输入解耦|ADR-017]] 定义；本决策继续约束真实帧、水平平面和永久纹理映射。
- 删除独立中心装饰框和伪切片边框；只显示真实切片自己的边界。

## 理由

- 静态纹理与实体平面一一映射，使“帧”和“空间位置”成为同一事实，消除中心播放器伪装成时间切片的结构问题。
- 固定 X-Y 正视相机保证所有帧构图一致，身体保持竖向中心关系，翅膀开合只来自源动作。
- 水平平面沿 Y 轴分层后，侧视图直接呈现不相交的平行层级，与用户示意一致。

## 影响

- ADR-013 的固定 Z 轴背景序列、ADR-014 的中心焦点纹理替换和 ADR-015 的局部轴跟随相机不再有效，三者均标记为 `superseded`。
- 视口输入已由 ADR-017 调整为普通滚轮缩放、`Alt + 滚轮` 逐帧穿梭，以保证 Blender 风格三维导航不被时间轴拦截。
- 91 张 768×768 PNG 仍全部预载，GPU 纹理开销需要在真实移动设备继续验证。

## 验证方式

- 资产检查必须得到 91 张连续 768×768 RGBA PNG，manifest 源帧为 1 到 91，且 `view: fixed-top-front`、`displayPlane: xz-horizontal`、`timelineAxis: y`。
- 静态检查 `src/main.js` 不存在 `focusLayer`、`focusTrail` 或运行时 `.map =`；每个切片仅在创建材质时接收自己的纹理。
- 浏览器截图检查收拢正视构图、展开水平分层、斜侧不相交结构和额外中心框缺失。
- 运行 `node --check src/main.js`、`python -m py_compile scripts/export_butterfly_slices.py`、`npm run build`、`git diff --check` 和 memory lint。
