# ADR-012｜平行深度切片排列

## 状态

`active`

## 背景

上一版将卡片沿世界 X 轴移动，但每张卡片的 Z 坐标都是 0。它们虽然在屏幕上看起来像一条直线，实际上全部位于同一个平面；当用户旋转到侧面时，卡片边缘会互相重叠，呈现一张被拉长的斜面，而不是参考图所表达的平行、有间隔、不相交的切片序列。

## 决策

- 继续使用 `offset = index - state.frameFloat`，让当前时间切片始终位于焦点原点。
- 每张卡片保持正面平行，沿卡片法线方向的世界 Z 轴分层：`x = 0`、`y = 0`、`z = -offset × SLICE_DEPTH_STEP × spread`。
- `SLICE_DEPTH_STEP = 0.42`，作为相邻时间切片之间的真实深度间隔；展开时只改变深度距离，不横向错位，不给单张切片增加旋转或曲线漂移。
- `rotationRig` 仍负责整体 yaw/pitch 视角；当前帧位于 `z = 0`，相机缩放仍以当前连续时间切片中心为焦点。
- 保留透明度分级、卡片边缘线、整体切片组呼吸和环境动效，但环境动效不得破坏卡片的平行和等距几何关系。

## 理由

- 沿法线分离才能让切片成为真正独立的平行平面，而不是共面图片列表。
- 正面通过透视看到嵌套层级，侧面通过深度间隔看到彼此分开的卡片边缘，符合“平行、有间隔、不相交”的空间语义。
- 当前帧始终在原点，播放裁切与滚轮聚焦不会因为布局轴改变而产生跳变。

## 影响

- 正面不再是 X 轴横向平铺，而是当前帧居中的深度嵌套。
- 侧面观察时卡片不再汇聚到同一平面；相邻切片通过 `0.42` 的深度步进保持独立。
- 展开按钮仍然只控制 `spread`，长按播放仍只推进 `frameFloat`，拖拽仍只控制统一转台的视角。
- 历史 X 轴共面方案由本 ADR 替代，旧 ADR 保留以供追溯，不得作为当前实现依据。

## 验证方式

- `src/main.js` 使用 `index - state.frameFloat` 和 `SLICE_DEPTH_STEP` 计算位置。
- 代码中不存在 `LINE_STEP`、旧的 X 轴布局或逐片旋转/漂移。
- 静态检查当前帧原点、`x/y = 0`、Z 深度步进、历史切片裁切和当前焦点逻辑。
- 运行 `node --check src/main.js`、`npm run build`、`git diff --check` 以及 wiki memory lint。
- 浏览器中复核正面嵌套、侧面间隔、拖拽旋转、播放和缩放焦点；未执行的手动检查必须在工作日志中明确记录。
