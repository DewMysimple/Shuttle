# ADR-010｜全动画安全构图

## 状态

`active`

## 背景

源 Blender 相机的初始构图适合兰花闭合的前段姿态，但花朵在后续动画中展开，投影会越过 PNG 的上侧和右侧边界。网页端只能显示已经导出的 PNG，无法恢复渲染阶段被裁掉的花瓣；仅在 Three.js 中移动卡片会把问题从一侧转移到另一侧。

## 决策

- 在 `scripts/export_blender_assets.py` 渲染切片前，遍历完整整数帧范围的评估模型包围盒。
- 保持源相机的观察方向，通过计算联合投影范围自动降低焦距，并用 `shift_x/shift_y` 将联合包围盒光学居中。
- 将联合投影收进约 8%–92% 的安全区域后再渲染 768×768 RGBA PNG；相机调整只存在于 Blender 导出进程，不写回源 `.blend`。
- 每次更换模型、动画或相机时都重新计算，不能复用旧的固定焦距和 shift 参数。

## 理由

- 以全动画联合包围盒为依据，可以保证闭合、展开中和完全展开的姿态都不会触碰透明画布边缘。
- 保留原相机方向，避免为了安全边距改变兰花的观察角度；自动 shift 让主体整体位于卡片中心附近。
- 预先在资产阶段解决裁剪，比在网页端对已经截断的纹理做平移或缩放更可靠。

## 影响

- 早期闭合帧相对原始构图会略小，这是为后段完全展开姿态让出安全空间的必要代价。
- 166 张 PNG 和可选 GLB 需要重新生成；网页端 Three.js 代码、时间隧道布局和交互职责不变。
- 资产验收增加 Alpha 边缘检查，至少抽查首帧、中段和尾帧，并验证全部帧没有 Alpha 包围盒触边。

## 验证方式

- Blender 导出日志显示相机适配后的投影范围约为 `(0.1172, 0.08, 0.8828, 0.92)`。
- 166 张 PNG 均生成成功；Alpha 包围盒触边数量为 `0`。
- 代表帧首帧、中段和尾帧均保留完整兰花；`npm run build`、`git diff --check` 和 memory lint 通过。
