# ADR-015｜蝴蝶正面跟随相机采样管线

## 状态

`active`

## 背景

用户指定的蝴蝶 `.blend` 含有 1–91 帧的翅膀拍动和沿路径飞行动画，但源文件自带的英雄相机是斜侧视角，会让蝴蝶在不同时间帧中转成侧面。网页主体需要始终保持蝴蝶正面，再把每个姿态作为时间切片使用。

## 决策

- 只使用名称带“展示_”前缀的三个蝴蝶网格，不渲染重复源对象、展示台或场景背景。
- 不使用、不修改源 `.blend` 的原相机；离线脚本为每帧创建临时相机，沿动画节点本地 `-X` 正面轴跟随，并保持固定采样距离。
- 按源场景 1–91 的每个整数帧输出 768×768 RGBA PNG，`slice-manifest.json` 的数量与 PNG 数量保持一致。
- 网页仍只加载透明 PNG，沿世界 Z 轴排列时间切片；不把 Blender 或实时 GLB 加入浏览器运行时。

## 理由

- 相机跟随动画节点的正面轴，可以去除源相机带来的斜侧视角，同时保留翅膀原本的开合节奏。
- 每张 PNG 的透明画布尺寸一致，便于 Three.js 的 `focusLayer` 做连续交叉淡化，固定深度切片继续提供时间轴纵深。
- 所有采样设置只存在导出进程，不会污染用户提供的源工程。

## 影响

- 当前运行资源从兰花 166 帧切换为蝴蝶 91 帧；旧兰花 PNG 和超出 91 的帧不再属于网页资源。
- 蝴蝶沿路径的平移不会作为原相机镜头运动写入 PNG；时间路径由逐帧姿态、固定时间切片深度和网页播放残影共同表达。
- 若未来要更换蝴蝶动作或正面轴，需要同步更新 `FRONT_ANCHOR_NAME`、正面方向和透明边缘检查。

## 验证方式

- Blender 导出日志成功保存 `frame-001.png` 至 `frame-091.png`。
- 抽查首帧、中段帧和尾帧，蝴蝶均在正面采样镜头内，翅膀拍动姿态可见，PNG 为 RGBA 且透明边缘未裁切。
- `slice-manifest.json` 标记 91 帧、`view: tracked-front`，网页资源检查确认 91 个文件连续存在。
- 运行 `node --check src/main.js`、`npm run build`、`git diff --check` 和 memory lint。
