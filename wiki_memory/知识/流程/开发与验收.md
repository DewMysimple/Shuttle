# 开发与验收

## 一句话结论

每次修改先验证代码和运行资产，再同步 wiki memory、执行 lint、提交并推送，保证代码、记忆和远程版本一致。

## 适用范围

所有前端、Blender 导出、视觉、交互、资产和文档修改。

## 详细内容

1. 开始前读取 `wiki_memory/AGENTS.md`、当前状态和相关知识/决策页。
2. 修改代码或资产；如有实质任务，在 `日志/` 新增一篇追加式日志。
3. 运行 `npm run build`，检查页面、manifest 和清单中的 166 张 PNG 的 HTTP 状态；确认网页不请求未使用的 GLB。
4. 新增日志后运行 `python 工具/memory_lint.py index`，再运行 `python 工具/memory_lint.py check`。
5. 检查 `git diff`、`git status`，提交并推送 `origin/main`。

## 常见问题或陷阱

- 不要只改 `PROJECT_MEMORY.md` 而不写结构化日志；历史过程应进入 `日志/`。
- lint 报孤儿页或断链时，不要用删除页面掩盖问题，应补入口链接。
- 导出脚本成功不等于网页成功，必须检查浏览器运行资产和页面请求。
