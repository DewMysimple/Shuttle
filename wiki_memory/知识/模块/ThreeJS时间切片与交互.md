# Three.js 时间切片与交互

## 一句话结论

`src/main.js` 管理 91 个永久绑定静态帧纹理的水平平面；时间播放通过选中或跟随不同 Y 轴实体平面完成，三维视口独立控制，不存在中心纹理播放器。

## 当前结构

- `initialise()` 先校验 manifest 的逐帧、视角、展示平面和时间轴契约，再分批载入 91 张 PNG。
- `createSlices()` 为每张纹理创建独立 `MeshBasicMaterial`，之后不再改变 `map`。每个根组旋转 `-90°` 到 X-Z 水平面。
- `updateTimeline()` 更新平面 Y 坐标、透明度、层间距和当前索引；只在包围体中心或当前帧枢轴自身发生位移时平移相机，不重建用户的旋转、平移和缩放结果。
- `shuttleTarget` 是时间位置。`Alt + 滚轮`、方向键和播放按钮以整数步进修改它；总览视口保持固定，当前帧视口跟随对应 Y 位置。
- `Alt + 左键` 比较指针到画布中心的径向距离，外拖增加 `spreadTarget`，内拖减少；普通左键完整保留给视口旋转。
- Three.js `OrbitControls` 是 Blender 风格三维控制层：中键旋转、`Shift + 中键` 平移、滚轮缩放，并兼容左键旋转和右键平移。
- `getPresetCamera()` 根据 91 层实时包围体计算透视、前视、侧视和当前帧视距；当前帧视图降低其他层透明度，避免沿法线观察时形成全帧叠糊。
- 切片的卡片、轮廓与 PNG 材质全部启用深度测试，不再按时间距离强制 `renderOrder`。

## 常见陷阱

- 不要增加固定在视觉中心并换纹理的平面，即使背景仍显示其他切片，这仍是伪时间切片。
- 不要把 91 个平面放在同一立面上横向重叠；平面必须水平、法线一致并沿 Y 轴分层。
- 不要增加独立中心边框冒充当前切片；所有卡片边界必须属于真实帧平面。
- 普通滚轮必须缩放三维视口；时间步进使用 `Alt + 滚轮`，两者不能重新合并到同一无修饰输入。
- 不要在每帧无条件重写相机位置或 `lookAt`；预设过渡结束后必须保留 `OrbitControls` 的旋转、平移和缩放结果。
- 改变透明度可以做视觉分级，但不能更换纹理或改变帧与平面的固定映射。
