# Three.js 时间切片与交互

## 一句话结论

`src/main.js` 用一个长按播放驱动的 Three.js 场景管理 manifest 中的 166 张透明切片、固定相机转台和环境动效；当前帧相对锚定在中心，其余可见帧沿 X 轴保持正面平行地组成直线时间序列；网页运行时不加载 GLB。

## 适用范围

修改时间映射、切片空间布局、拖拽旋转、相机、灯光或渲染循环时参考本页。

## 详细内容

- `loadSlices()` 先读取 manifest 的 `count`，当前为 166；左键长按超过 260ms 后 `frameFloat` 按 30fps 从当前帧向 165 播放，右键长按则向 0 倒放。
- 播放状态用 `frameFloat` 更新切片的空间位置、透明度和高亮，不创建 `AnimationMixer`；松开指针会暂停播放，播放期间仍可更新视角。右侧“正放”“倒放”按钮单击启动对应方向，再次点击当前方向暂停；“开头”“结尾”按钮暂停并定位到首帧或尾帧。
- 每次更新切片时使用 `currentFrameIndex = floor(frameFloat)`；`index < currentFrameIndex` 的历史切片设为 `visible = false`，其余切片继续按距离分级渲染。倒放回到较早帧时，切片根据新的门槛恢复可见。
- 每张切片由卡片、边缘线和透明 PNG 平面组成；卡片尺寸为 `2.15 × 1.72`，图片尺寸为 `1.92 × 1.54`，`spread` 乘以 X 轴 `LINE_STEP = 0.30` 展开，Y/Z 坐标和切片自身旋转保持为 0。
- 正面强调当前帧与直线序列：中心约 `0.92`，邻近帧按距离衰减，中远帧继续保留低透明度轨迹；旋转到侧面时通过视角透视和边缘线辨认平行切片，不再依赖 X/Z 隧道或逐片倾斜。
- 当前帧和近帧通过运行时 shader 的 `sliceSaturation`、`sliceContrast` 增强主体色彩，不改写 PNG；CSS 白色 screen 雾层保持低覆盖度。
- “展开切片”按钮只更新 `spreadTarget`；拖拽不再改变展开状态。
- 拖拽超过 8px 起拖死区后双轴独立更新：横向增量更新不封顶的 `yawTarget`，每个视口宽度约响应 333°；纵向向下拖动增加俯视角、向上拖动减少俯视角，更新 ±45° 范围内的 `pitchTarget`；斜向手势同时影响两个角度，播放期间不屏蔽该路径。
- `rotationRig` 只承载时间切片，固定相机只提供稳定透视；拖拽时用 14、释放时用 8 的更快无惯性阻尼过渡，`R` 恢复默认视角。
- `wheel` 只修改相机距离目标值，目标范围为 `3–15.5`，使用更快但可打断的阻尼平滑缩放；相机始终对准当前 `frameFloat` 的连续时间切片中心，不触碰 `frameFloat` 或旋转角度。
- `updateAtmosphere()` 只维护独立的低幅度粒子、轨道光环和光晕动效，不跟随用户视角明显旋转。

## 常见问题或陷阱

- 不要把 `yawTarget` 归一化到 0–2π，否则连续拖拽时会在边界产生跳变。
- 不要在展开按钮中重置视角，展开和观察应是两个独立状态。
- 不要让相机、主体和切片组分别响应同一个用户旋转量，否则会产生叠加视差和眩晕。
- 不要把屏幕 Y 轴方向写反：浏览器坐标的 `deltaY > 0` 必须让 `pitchTarget` 增加，从而实现下拖俯视、上拖仰视；当前俯仰限制为 ±45°。
- 不要重新引入单轴方向锁定；8px 只负责避免误触，死区后两个轴都应消费各自的增量。
- 反向拖拽必须继续累加，不能重新以起点计算造成跳变。
- 不要把 `frameFloat` 只用于透明度；如果空间位置重新使用固定时间中点，当前帧就不会保持中心，直线时间序列也会失去时间穿梭感。
- 不要让全部切片使用近似相同的不透明度；必须保持当前、近距、中距、远距四级层次。
- 不要把页面滚动重新接回 `frameFloat`；时间轴播放入口是长按画布，滚轮入口是相机距离。
- 长按定时器必须在超过 8px 的拖拽开始时取消，否则用户旋转时会误触发播放；长按已触发播放后，指针移动应继续改变旋转，不能提前 return。
- 单屏主界面使用 `touch-action: none`；修改触摸行为时必须保留长按播放和拖拽分流，不能让浏览器默认手势抢占画布。
