# Three.js 时间切片与交互

## 一句话结论

`src/main.js` 用一个长按播放驱动的 Three.js 场景管理 manifest 中的 166 张透明切片、固定相机转台和环境动效；时间轴切片固定在世界 Z 轴等距深度序列中，独立 `focusLayer` 将当前/下一帧稳定放在视觉中心并连续交叉淡化，播放时用最多 5 层横深 `playbackTrail` 和固定时间轴内低透明度 `playbackCursor` 补充轨迹与穿越感；网页运行时不加载 GLB。

## 适用范围

修改时间映射、切片空间布局、拖拽旋转、相机、灯光或渲染循环时参考本页。

## 详细内容

- `loadSlices()` 先读取 manifest 的 `count`，当前为 166；左键长按超过 260ms 后 `frameFloat` 按 30fps 从当前帧向 165 播放，右键长按则向 0 倒放。
- 播放状态只用 `frameFloat` 更新时间焦点，不创建 `AnimationMixer`，也不推动整组切片沿 Z 轴移动；松开指针会暂停播放，播放期间仍可更新视角。右侧“正放”“倒放”按钮单击启动对应方向，再次点击当前方向暂停；“开头”“结尾”按钮暂停并定位到首帧或尾帧。
- 时间轴每张切片的位置使用固定 `timelineCenter = (sliceCount - 1) / 2`；历史、当前和未来切片均保持 `visible = true`，固定空间结构只按时间轴距离保持低存在感。`focusLayer` 使用 `floor(frameFloat)`、`ceil(frameFloat)` 和小数部分做当前/下一帧连续交叉淡化，当前帧变化不会造成矩形卡片跳变。
- 每张切片由卡片、边缘线和透明 PNG 平面组成；卡片尺寸为 `2.15 × 1.72`，图片尺寸为 `1.92 × 1.54`，`spread` 乘以 Z 轴 `SLICE_DEPTH_STEP = 1` 展开；切片 X/Y 坐标和自身旋转保持为 0。收拢时只突出 `Math.round(frameFloat)` 对应的当前切片，其余重叠帧淡出。
- 正面强调当前焦点与固定深度序列：焦点图像约 `0.99`，播放时固定时间轴卡片、轮廓和远端图像整体降噪但不消失；`playbackCursor` 按当前帧到固定切片的距离连续衰减，附近切片获得有限轮廓、图像和微光增强。最多 5 层轨迹残影使用约 `0.11/0.075/0.05/0.032/0.02` 的递减透明度，同时使用横向 `0.09` 与 Z 轴 `0.085` 间距，不显示额外卡片边框。旋转到侧面时通过真实深度间距和低透明边缘线辨认平行切片。
- 当前焦点通过运行时 shader 的 `sliceSaturation`、`sliceContrast`、`sliceWarmth` 和独立透明纹理副层增强主体色彩；当前焦点饱和度最高约 `1.90`、对比度最高约 `1.29`，副层使用暖珊瑚色 `AdditiveBlending`，只按 `frameFloat` 连续焦点权重显示，约 `1.7s` 周期低幅度呼吸，不改写 PNG。CSS 白色 screen 雾层与 haze 呼吸保持低覆盖度，并在主体背后增加低强度深玫红对比区。
- “展开切片”按钮只更新 `spreadTarget`；拖拽不再改变展开状态。
- 拖拽超过 8px 起拖死区后双轴独立更新：横向增量更新不封顶的 `yawTarget`，每个视口宽度约响应 396°；纵向向下拖动增加俯视角、向上拖动减少俯视角，每个视口约响应 120°并更新 ±90° 范围内的 `pitchTarget`；斜向手势同时影响两个角度，播放期间不屏蔽该路径。
- `rotationRig` 只承载时间切片，固定相机只提供稳定透视；拖拽时用 18、释放时用 10 的更快无惯性阻尼过渡，横向每视口约 396°、纵向每视口约 120°，`R` 恢复默认视角。
- `wheel` 只修改相机距离目标值，目标范围为 `3–15.5`，使用更快但可打断的阻尼平滑缩放；相机不再随 `frameFloat` 产生额外漂移，并以 `CAMERA_FOCUS_Y = 0.04` 对准主焦点平面，不触碰 `frameFloat` 或旋转角度。
- `updateAtmosphere()` 只维护独立的低幅度粒子、轨道光环和光晕动效，不跟随用户视角明显旋转；播放时仅给环线和 halo 增加局部低幅亮度，中心主焦点使用 `0.108 ± 0.024` 暖珊瑚光晕。
- 轨道光环的 `forEach` 回调必须声明 `(ring, index)`，因为播放增益按环线序号衰减；修改环境层时需优先运行时检查，避免 JavaScript 异常使整个 `requestAnimationFrame` 停止而只剩 DOM UI。

## 常见问题或陷阱

- 不要把 `yawTarget` 归一化到 0–2π，否则连续拖拽时会在边界产生跳变。
- 不要在展开按钮中重置视角，展开和观察应是两个独立状态。
- 不要让相机、主体和切片组分别响应同一个用户旋转量，否则会产生叠加视差和眩晕。
- 不要把屏幕 Y 轴方向写反：浏览器坐标的 `deltaY > 0` 必须让 `pitchTarget` 增加，从而实现下拖俯视、上拖仰视；当前俯仰限制为 ±90°。
- 不要重新引入单轴方向锁定；8px 只负责避免误触，死区后两个轴都应消费各自的增量。
- 反向拖拽必须继续累加，不能重新以起点计算造成跳变。
- 不要让 `frameFloat` 推动整个时间轴空间；播放焦点应由独立 `focusLayer` 稳定在中心，固定时间轴只表达空间结构，二者职责必须分离。
- 如果播放中的纵深感不足，优先增强固定时间轴内的 `playbackCursor`、横深残影和局部通道光晕；不要通过恢复整组切片平移来补偿，否则会重新产生卡片扫过镜头的切片感。
- 不要让全部切片使用近似相同的不透明度；必须保持当前、近距、中距、远距四级层次。焦点微光只允许作用于当前连续时间焦点，不能给整组切片统一加光。
- 不要把页面滚动重新接回 `frameFloat`；时间轴播放入口是长按画布，滚轮入口是相机距离。
- 播放时不要给所有切片增加同等饱和度、高光或轮廓；主焦点与有限残影承担主体信噪比，卡片结构应降噪而不是扩散焦点。
- 长按定时器必须在超过 8px 的拖拽开始时取消，否则用户旋转时会误触发播放；长按已触发播放后，指针移动应继续改变旋转，不能提前 return。
- 单屏主界面使用 `touch-action: none`；修改触摸行为时必须保留长按播放和拖拽分流，不能让浏览器默认手势抢占画布。
