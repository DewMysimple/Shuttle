# 2026-08-30｜Windows 启动脚本修复

- 时间：2026-08-30（北京时间）
- 类型：`bug`
- 状态：`完成`
- 目标：修复双击 `runStart.cmd` 无法启动工程的问题。
- 日志索引：[[日志/MOC_工作日志|工作日志 MOC]]

## 已确认的决策

- 批处理脚本使用 `%~dp0` 获取脚本所在目录，不能写成 `%~dp`。
- 双击入口需要对 Node.js、npm 和依赖缺失给出可见错误或自动处理。

## 检查与操作

- 检查原脚本，确认目录变量少了参数编号 `0`。
- 增加 Node.js/npm PATH 检查、依赖检查、自动安装和启动提示。
- 更新 README、项目记忆和运维知识页。

## 文件变更

- 修改 `runStart.cmd`。
- 更新 `README.md`、`PROJECT_MEMORY.md`、项目概览和本地运行知识页。

## 测试与验证

- 确认工程目录存在 `node_modules/.bin/vite.cmd`。
- 使用 `npm run build` 验证启动入口对应的工程仍可正常构建。

## 待确认长期记忆

- `runStart.cmd` 是 Windows 用户的标准双击启动入口。

## 问题、结果与下一步

- 结果：脚本现在会从自身目录启动 Vite，依赖不存在时自动安装。
- 遗留问题：如果系统没有 Node.js，仍需先安装 Node.js LTS。
