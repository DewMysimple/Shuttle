# 系统架构

> 只记录当前有效的模块关系、数据流、运行方式和关键技术边界。

## 架构概览

浏览器加载 Vite 页面后，Three.js 加载 `flower.glb` 和 76 张透明 PNG。页面滚动进度同时驱动 GLB morph animation 的时间和当前帧高亮；画布 Pointer Events 驱动固定相机转台的方位角和轻微俯仰，展开按钮独立驱动切片展开；渲染循环负责短阻尼过渡、主体漂浮、切片漂移、粒子和光环。

## 模块关系

| 模块 | 职责 | 依赖 | 入口 |
| --- | --- | --- | --- |
| 页面入口 | HTML 结构和无障碍标签 | `src/main.js`、`src/style.css` | `index.html` |
| Three.js 场景 | GLB、灯光、相机、AnimationMixer、时间切片 | `three`、运行资产 | `src/main.js` |
| Blender 导出 | Alembic MeshSequenceCache 烘焙为 morph targets，并渲染透明切片 | Blender 5、外部 ABC 缓存 | `scripts/export_blender_assets.py` |
| 结构化记忆 | 当前状态、决策、知识、日志和 lint/index | Markdown、Python 标准库 | `wiki_memory/` |

## 数据流或请求流

1. `scrollProgress` 由 `.slice-section` 的滚动位置计算。
2. `frameFloat = scrollProgress × 75`，同时调用 `mixer.setTime()`。
3. `spreadTarget` 控制 76 张卡片沿 X/Z 轴展开。
4. 拖拽超过死区后按主方向锁定：横向增量累积不封顶的 `yawTarget`，纵向增量更新 ±28° 范围内的 `pitchTarget`。
5. `rotationRig` 同时承载兰花和时间切片；相机保持固定，`requestAnimationFrame` 以短阻尼将目标角度呈现出来。

## 运行与部署

开发环境执行 `npm install`、`npm run dev`；生产环境先执行 `npm run build`，再由静态服务器托管 `dist/`。部署时必须同时提供 `public/assets/flower.glb` 和 76 张 PNG 运行资产。
