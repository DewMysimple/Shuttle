# 系统架构

> 只记录当前有效的模块关系、数据流、运行方式和关键技术边界。

## 架构概览

浏览器加载 Vite 页面后，Three.js 先读取 `slice-manifest.json`，再加载清单中的 166 张透明 PNG。画布左键长按正向播放、右键长按倒放，右侧“正放”“倒放”单击启动或暂停对应方向，“开头”“结尾”单击定位边界；`frameFloat` 按源动画 30fps 前进或后退，但只负责时间焦点。时间轴切片以时间中点为固定空间中心，沿世界 Z 轴平行分层并以 `SLICE_DEPTH_STEP = 1` 等距排列；独立 `focusLayer` 固定在视觉中心，用当前/下一帧纹理连续交叉淡化，播放时再叠加最多 5 层低透明度 `playbackTrail`，而固定卡片结构降噪。收拢时由主焦点层保证当前时间切片可见；画布 Pointer Events 同时驱动固定相机转台的方位角和 ±90° 俯仰，播放期间仍可旋转，横向每个视口约响应 396°、纵向约响应 120°，Wheel 只驱动 3–15.5 的相机距离缩放，展开按钮独立驱动切片展开；渲染循环负责播放、焦点交叉淡化、轨迹残影、缩放阻尼、整体切片呼吸、粒子和光环。

## 模块关系

| 模块 | 职责 | 依赖 | 入口 |
| --- | --- | --- | --- |

| 结构化记忆 | 当前状态、决策、知识、日志和 lint/index | Markdown、Python 标准库 | `wiki_memory/` |

## 数据流或请求流

1. 长按计时器超过 260ms 后进入播放，`frameFloat` 按 30fps 连续增加；松开或到达末帧后暂停。
2. 右侧播放按钮可直接改变播放状态；“开头”“结尾”会先暂停，再将 `frameFloat` 设为 0 或 165。
3. `frameFloat` 当前清单范围为 0–165；每张时间轴切片的位置由固定 `timelineCenter = (sliceCount - 1) / 2` 计算，所有切片保持 `visible = true`，历史、当前和未来帧都保留在固定空间结构中。
4. `spreadTarget` 控制 166 张卡片沿世界 Z 轴（卡片法线方向）展开，使用 `SLICE_DEPTH_STEP = 1` 拉开相邻平行切片的真实深度距离；每张卡片保持正面平行，不额外旋转、弯曲或横向错位。`focusLayer` 不参与时间轴位移，而是把当前/下一帧稳定显示在视觉中心；播放期间 `playbackTrail` 只提供有限低透明度轨迹，暂停后平滑退出。
5. 拖拽超过死区后双轴独立更新：横向增量累积不封顶的 `yawTarget`，纵向按“下拖俯视、上拖仰视”更新 ±90° 范围内的 `pitchTarget`；当前每个视口约响应 `396°/120°`，斜向手势同时影响两个角度；播放期间继续走同一旋转路径。
6. `rotationRig` 只承载时间切片；相机保持固定视点，Wheel 修改相机距离，`requestAnimationFrame` 以可打断阻尼呈现旋转和缩放目标。

## 运行与部署

开发环境执行 `npm install`、`npm run dev`；生产环境先执行 `npm run build`，再由静态服务器托管 `dist/`。部署时必须提供 `slice-manifest.json` 和清单声明的 166 张 PNG；`flower.glb` 是可选导出检查资产，不是页面运行依赖。
