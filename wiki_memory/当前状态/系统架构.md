# 系统架构

> 只记录当前有效的模块关系、数据流、运行方式和关键技术边界。

## 架构概览

浏览器加载 Vite 页面后，Three.js 先读取 `slice-manifest.json`，再加载清单中的 166 张透明 PNG。画布左键长按正向播放、右键长按倒放，右侧“正放”“倒放”单击启动或暂停对应方向，“开头”“结尾”单击定位边界；`frameFloat` 按源动画 30fps 前进或后退，当前帧通过 `index - frameFloat` 锚定在视觉中心，`index < floor(frameFloat)` 的历史切片从渲染中隐藏，未播放切片沿世界 Z 轴平行分层并以 `SLICE_DEPTH_STEP = 0.42` 等距排列；画布 Pointer Events 同时驱动固定相机转台的方位角和 ±45° 俯仰，播放期间仍可旋转，横向每个视口宽度约响应 333°，Wheel 驱动以当前时间切片连续中心为焦点的 3–15.5 相机距离缩放，展开按钮独立驱动切片展开；渲染循环负责播放、缩放阻尼、整体切片呼吸、粒子和光环。

## 模块关系

| 模块 | 职责 | 依赖 | 入口 |
| --- | --- | --- | --- |
| 页面入口 | HTML 结构和无障碍标签 | `src/main.js`、`src/style.css` | `index.html` |
| Three.js 场景 | 透明纹理、时间切片卡片、相机、统一转台和环境动效 | `three`、166 张 PNG | `src/main.js` |
| Blender 导出 | Alembic MeshSequenceCache 烘焙为 morph targets，扫描全动画包围盒后适配相机并渲染透明切片 | Blender 5、外部 ABC 缓存 | `scripts/export_blender_assets.py` |
| 结构化记忆 | 当前状态、决策、知识、日志和 lint/index | Markdown、Python 标准库 | `wiki_memory/` |

## 数据流或请求流

1. 长按计时器超过 260ms 后进入播放，`frameFloat` 按 30fps 连续增加；松开或到达末帧后暂停。
2. 右侧播放按钮可直接改变播放状态；“开头”“结尾”会先暂停，再将 `frameFloat` 设为 0 或 165。
3. `frameFloat` 当前清单范围为 0–165；每张切片的 `offset = index - frameFloat`，且当 `index < floor(frameFloat)` 时设置 `visible = false`，避免历史切片继续出现在相机前方。
4. `spreadTarget` 控制 166 张卡片沿世界 Z 轴（卡片法线方向）展开，使用 `SLICE_DEPTH_STEP = 0.42` 拉开相邻平行切片的真实深度距离；每张卡片保持正面平行，不额外旋转、弯曲或横向错位。
5. 拖拽超过死区后双轴独立更新：横向增量累积不封顶的 `yawTarget`，纵向按“下拖俯视、上拖仰视”更新 ±45° 范围内的 `pitchTarget`，斜向手势同时影响两个角度；播放期间继续走同一旋转路径。
6. `rotationRig` 只承载时间切片；相机保持固定视点，Wheel 修改相机距离，`requestAnimationFrame` 以可打断阻尼呈现旋转和缩放目标。

## 运行与部署

开发环境执行 `npm install`、`npm run dev`；生产环境先执行 `npm run build`，再由静态服务器托管 `dist/`。部署时必须提供 `slice-manifest.json` 和清单声明的 166 张 PNG；`flower.glb` 是可选导出检查资产，不是页面运行依赖。
